# 智语外呼技术方案书

作品使用京东 POP 资审驳回任务作为参赛场景。它把浏览器实时语音、业务处理和质量验证放在同一条可回放的链路中。完成状态以模拟业务系统的结构化回执为准。

## 赛题要求与系统对应

| 赛题能力 | 项目实现与验收证据 |
|---|---|
| WebRTC 多轮实时语音 | 原生浏览器 JavaScript 与 Python aiortc 双向传输 Opus 音频。控制通道传输实时转写、阶段、打断、时延和结果。文字与麦克风共用会话状态和语音播报，关闭麦克风后仍可收听。在播报期间提交的文字等待本轮音频发完再处理。 |
| 流式识别与端点 | Zipformer 小型中文 CTC 流式识别，Silero VAD 对 32 毫秒窗口做起止检测，前置缓存保留开头音节，增量识别与终稿分别展示。领域词表归一化“京麦”“授权书”等易错词。 |
| 合成、打断、双讲和弱网 | MeloTTS 中文分句合成，先推首段，后续段并行于播放。服务启动时预合成已校验的常用回复首段。浏览器请求回声消除、降噪和自动增益，机器人播报期间继续监听近端输入，检测到讲话即停止当前音频并取消后续待播。记录 RTP 丢包、抖动和 RTT。 |
| 六段任务闭环 | 开场自报智能客服身份 → 负责人确认 → 需求确认 → 驳回原因与整改方案 → 用户确认 → 结构化回写。对错误身份、未知规则、未接通、回电、二次失败、三次同类问题和投诉分别处理。 |
| 多轮纠错与知识溯源 | 状态机持有身份、需求、业务单据、上个有依据的回复和确认状态。问句经词表纠正、别名和字符检索匹配。可配置本地 Qwen 选择条目，也可为文字和语音接入独立的第三方问答模型，从获准的候选中识别最多两个知识主题及答复语气。答复内容与引用来自本地知识库。对低把握问题主动追问，缺失材料或复杂争议登记人工复核。 |
| 工具调用、幂等与异常 | 服务端按状态调用名单查询、受控单据读取、工单登记与结果回写。Pydantic 校验字段，SQLite 事务对会话键去重，同键同参数重放返回同一回执，冲突参数拒绝。异常保留待回写状态并支持重试。 |
| 全量质检与合规 | 可导出会话事件、转写和按需保存的双声道音频。播报前检查禁语、个人信息和身份状态，拒绝用户诱导，拒绝承诺审批结果。质检统计阶段、回写、证据、拦截、失败、打断和语音时延。 |
| RSI、评测与回滚 | 固定种子合成多轮商家脚本和对抗输入。按固定规则评分，本地可选 LLM-as-Judge 做语义抽检。失败聚类后从有来源标注的开发问句挖掘候选触发短语，生成版本化补丁。开发集提升、回归集原有成功样本零退化及合规门禁通过后才激活，已开始的电话固定使用创建时版本。 |
| 工程交付 | 启动脚本、Dockerfile、依赖和模型下载工具、源表校验、单元测试、浏览器验收、提交材料和模型许可证清单。 |

## 数据与场景路由

工作台本地加载「场景汇总」第 13–80 行，共 68 条规则，其中电话 54 条、京麦驳回 14 条。五个一级分类分别为品牌 33 条、入驻 25 条、行业资质 4 条、公司资质 4 条和商品资质 2 条。导入器按合并范围解析三级分类与话术，E28 和 E59 分别继承 E27 和 E58，校验规则总数、渠道分布和已复核的内容指纹。每条规则对应一张可处理单据，话术使用人工整理的驳回原因及整改指引，以原表行号及话术单元格为依据。单据真实字段未提供时，引导商家核对京麦原单。问题口径覆盖 11 条高频问答和 17 条有答复的特殊场景问答，依据场景限制匹配。

路由按回电或投诉标记、同场景提交次数和原始渠道决策。联系次数通过回联工单独立记录。首次提交电话未接后转京麦。第二次提交的首次联系未接生成回联工单，领取后再次未接转京麦。三次及以上同场景提交默认走京麦，有优先回联标记时走电话。信息缺失、用户要求转人工或投诉时登记人工复核。电话通知完成与直接京麦处理均生成书面回执，关单、通知和工单在同一事务内写入。领取中的回联工单禁止重复领取，主动结束或连接未建立时释放，完成后关闭。沙箱使用脱敏或合成单据，语音交互通过浏览器完成。

## 技术与时延预算

浏览器捕获近端单声道，经 WebRTC 发送到 aiortc，服务端重采样为 16 kHz。VAD 检测起点后将预滚和当前窗口喂给流式 ASR，对话策略在终稿到达后处理业务状态。合成音频重采样为 48 kHz，以 20 毫秒帧回传。打断时清空当前代的帧队列，旧任务完成后的帧无法进入新播报。

规则允许使用开源语音模型或等价云服务。当前采用 CPU 可运行的 Zipformer、Silero 和 MeloTTS。本地 Qwen 可做 FAQ 匹配与语义评测。第三方问答配置独立，通过可编辑的提示词和受限的 JSON 输出协助组合知识答复。知识正文留在本机，云端请求使用经字段处理的当前模拟问题与通用话题，身份、路由与回写由状态机执行。模型请求超时或给出无效选择时，使用本地匹配或澄清。

| 阶段 | 设计预算 |
|---|---:|
| 浏览器采集、上行、抖动缓冲 | 180 ms |
| VAD 尾静音、流式 ASR 定稿 | 550 ms |
| 检索、合规、Mock 处理 | 180 ms |
| 首段语音队列与出包 | 175 ms |
| 下行与浏览器首次非静音输出 | 300 ms |
| 合计目标 | 1,385 ms |

上述预算适用于已预热的常用路径。模型服务参与低置信匹配或首次合成新句段会增加延迟。记录浏览器估算的「语音结束至播放」及服务端「VAD 估算结束至音频出包」两套数据，正式成绩用企业统一定义。启动、模型下载不计入单轮响应。离线模式费用为零云调用费，需留出模型磁盘和本机 CPU、内存。

## 回归与版本

测试数据以表达模板成组拆分。开发集用于挖掘补丁，回归集在同一固定规则口径下门控并重放已加载的 68 条原表规则，封存集在版本选择后比较。原始 JSON 带用例哈希、输入、逐轮输出、暂定和最终分数以及模型语义抽检。当前补丁限定为受控 FAQ 匹配别名，规则、合规门槛及评分口径保持独立。

参赛团队可按 V3 的既有岗位填报实际贡献。媒体链路和 Web 前端需要联调，业务策略负责人维护数据口径，评测负责人保管独立测试集，方案和演示负责人汇总可复现的结果。个人贡献及校赛报名信息以队伍实填为准。

## 赛场替换与交付

更换业务材料时，应审查场景包的来源、身份核验条件、必说项及字段，然后在工具网关适配官方接口。先使用模拟名单验证 WebRTC 和六段闭环，随后在被授权的沙箱复测。若云服务受限，可用现有离线组合。评委现场允许打断，演示依次展示实时交互、任务回写和质检，RSI 版本记录用于答辩。
